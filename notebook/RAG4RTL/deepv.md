# DeepV：一个用于Verilog代码生成的模型无关检索增强框架

## 引言

随着大语言模型（LLMs）在现代技术中的广泛应用，代码生成已成为一个重要的研究方向，这一趋势自然延伸到了硬件设计自动化领域。然而，现有的基于LLM的寄存器传输级（RTL）代码生成方法存在明显缺陷：它们无法将新型IP集成到模型的知识库中，导致生成的代码质量不佳。此外，随着通用LLM的不断进步，基于旧模型的微调方法将难以竞争。

为解决这些问题，佛罗里达大学的研究团队提出了**DeepV**——一个模型无关的检索增强生成（RAG）框架，专门用于Verilog RTL代码生成。

## 核心创新

### 1. 高质量知识库
DeepV的核心优势在于其使用了**VerilogDB**这一高质量数据集作为知识库：
- 包含20,392个Verilog模块（总计751MB代码）
- 源自GitHub、OpenCores和学术材料等可靠来源
- 每个模块都经过严格的预处理验证，确保语法正确性和可综合化
- 使用Icarus Verilog编译器进行语法验证，Yosys进行逻辑综合检查

### 2. 模型无关的RAG架构
与现有方法不同，DeepV具有以下特点：
- **无需微调**：不依赖特定模型的内部权重，适用于任何LLM
- **动态检索**：采用多阶段动态检索过程，根据查询复杂度自适应选择相关文档数量
- **成本效益**：知识库可轻松更新，无需重新训练整个模型

### 3. 智能检索优化
DeepV实现了多种预检索优化技术：
- 使用all-MiniLM-L6-v2嵌入模型生成384维向量
- 基于FAISS的高效相似性搜索
- 动态采样算法，根据相关性得分的下降率自动确定检索文档数量
- 设置最小相关性阈值（0.55）过滤低质量结果

## 实验结果

### 在VerilogEval基准上的表现
DeepV在标准VerilogEval基准测试中取得了显著成果：

**功能正确性提升：**
- GPT-5 Chat：pass@1提升16%，pass@10提升13%
- GPT-4o：pass@1提升8.7%，pass@10提升5.8%
- Gemini 2.5 Flash：pass@1提升18.5%，pass@10提升7.1%

**超越现有技术：**
- pass@1达到76.9%，比之前最佳的CraftRTL高出8.9%
- pass@5达到81.3%，比Veriseek高出4.4%
- pass@10达到83.3%，比Veriseek高出1.6%

### 复杂层次化IP生成
DeepV在生成复杂多模块IP方面表现出色：
- **FIR滤波器**：功能准确率从基线提升30%，动态采样下达到100%
- **Sobel滤波器**：准确率提升50%
- **安全随机数生成器(SRNG)**：准确率提升30%
- **UART模块**：准确率提升10%

## 系统架构

DeepV的工作流程包含三个主要阶段：

1. **知识库准备**：将VerilogDB中的每个模块构建成结构化文档，包含模块名称、自然语言描述、端口列表和完整代码

2. **动态上下文检索**：用户查询被转换为向量，在FAISS索引中搜索最相关的示例

3. **增强代码生成**：检索到的示例与原始查询结合，形成增强提示，指导LLM生成最终RTL代码

## 实际应用与可访问性

研究团队已将DeepV部署在Hugging Face Space上（https://huggingface.co/spaces/FICS-LLM/DeepV），提供：
- Web界面，无需安装或专用硬件
- 支持多种OpenAI模型（GPT-4o、GPT-4.1、GPT-5 Chat）
- 可配置的RAG参数和LLM参数
- API接口，便于集成到更大的系统或代理工作流中

## 关键洞察

1. **高质量知识库的重要性**：精心策划的知识库结合RAG框架，可以使通用LLM的性能媲美甚至超越专门微调的模型

2. **上下文需求的查询依赖性**：单个高度相关的示例通常就能提供显著性能提升，但复杂的查询需要动态的上下文检索策略

3. **模型无关设计的价值**：这种设计允许框架持续受益于通用LLM的进步，而无需昂贵的重新训练

## 未来展望

DeepV的成功为LLM驱动的EDA研究开辟了新方向：
- 探索更复杂的检索机制，如基于硬件感知的度量
- 将DeepV集成到更大的代理工作流中，实现RTL生成、自修正、测试平台生成等全流程自动化
- 将核心原理扩展到其他硬件生命周期任务，如安全linting和功能验证

DeepV不仅是一个实用的RTL代码生成工具，更为硬件设计自动化领域的研究提供了新的范式——通过高质量知识库和智能检索来增强通用LLM的能力，而非依赖昂贵的模型微调。

# DeepV动态上下文检索实例详解

DeepV的动态上下文检索是其核心创新之一，它能够根据查询的复杂度自适应地选择最相关的文档数量。让我通过一个具体的例子来说明这个过程。

## 工作流程示例

假设用户输入查询："生成一个8位FIR滤波器模块，包含时钟、复位、输入数据和输出数据端口"

### 第一阶段：向量化和初步检索
1. **查询向量化**：用户的自然语言查询被转换为384维向量
2. **FAISS搜索**：在包含20,392个Verilog模块的数据库中搜索相似度最高的10个候选文档
3. **相关性评分**：系统计算每个候选文档与查询的相关性得分

假设检索到的前5个候选文档及其相关性得分如下：
- 文档1 (FIR滤波器实现)：得分 0.85
- 文档2 (数字滤波器模块)：得分 0.78  
- 文档3 (信号处理IP)：得分 0.65
- 文档4 (DSP加速器)：得分 0.52
- 文档5 (音频处理模块)：得分 0.48

### 第二阶段：阈值过滤
系统应用0.55的最小相关性阈值：
- 文档1、2、3通过（得分≥0.55）
- 文档4、5被过滤掉（得分<0.55）

### 第三阶段：动态采样算法
现在系统分析相关性得分的下降率：

1. **初始设置**：
   - 总是包含最相关的文档1
   - 包含文档2以建立初始下降基准
   
2. **计算得分下降**：
   - Δprev = 0.85 - 0.78 = 0.07（文档1到文档2的下降）
   - Δcurr = 0.78 - 0.65 = 0.13（文档2到文档3的下降）

3. **判断是否继续**：
   - 检查条件：Δcurr > α × Δprev
   - 0.13 > 1.5 × 0.07 = 0.105 ✓
   - 由于当前下降率超过阈值1.5倍，算法停止

4. **最终结果**：只选择文档1和文档2作为上下文

## 算法优势体现

这种动态方法相比固定数量检索有明显优势：

**对于简单查询**（如"8位加法器"）：
- 可能只有一个高度相关的文档（得分0.92）
- 其他文档得分急剧下降（0.92 → 0.65 → 0.45）
- 动态算法只选择1个文档，避免无关信息干扰

**对于复杂查询**（如"多通道UART通信模块"）：
- 可能有多个高度相关的文档（0.88 → 0.85 → 0.83 → 0.79）
- 得分下降平缓，算法会选择更多文档（最多5个）
- 提供更丰富的上下文信息

## 实际效果

论文中的案例研究表明：
- **FIR滤波器**：动态采样比单文档检索将准确率从90%提升到100%
- **Sobel滤波器**：单文档就足够，动态采样和单文档效果相同
- **UART模块**：需要多个相关文档才能获得最佳效果

这种智能的动态检索机制确保了：
1. **效率**：避免不必要的计算开销
2. **准确性**：提供恰到好处的上下文信息
3. **适应性**：自动适应不同复杂度的查询需求

通过这种方式，DeepV能够在保持高效的同时，为每个查询提供最优的上下文支持，这正是其超越传统固定上下文RAG系统的关键所在。

# DeepV如何将Verilog代码进行结构化处理

DeepV框架对Verilog代码的结构化处理是其成功的关键因素之一。通过精心设计的预处理流程，DeepV将原始的Verilog代码转换为包含丰富元数据的结构化文档，为后续的检索增强生成提供了高质量的知识基础。

## 1. 高质量数据源：VerilogDB

DeepV使用**VerilogDB**作为其知识库，这是一个专门为LLM驱动的RTL生成而构建的高质量数据集：
- **规模**：包含20,392个Verilog模块（总计751MB代码）
- **来源**：GitHub、OpenCores和学术材料等可靠来源
- **覆盖范围**：涵盖组合逻辑、时序逻辑、定制加速器、外设接口和基本数字构建块等主要RTL设计类别

## 2. 严格的预处理验证

每个Verilog模块都经过严格的双重验证流程：

### 语法验证
- 使用**Icarus Verilog (iVerilog) 编译器**进行语法检查
- 确保所有代码在语法上完全正确

### 综合性验证  
- 使用**Yosys**进行逻辑综合检查
- 验证代码是否可综合，避免包含不可综合的SystemVerilog构造
- 确保所有模块都能转换为实际的硬件电路

## 3. 结构化文档构建

DeepV为每个Verilog模块构建一个结构化的文本文档，如图2所示。这个文档不是简单的原始代码，而是包含以下关键组件的完整描述：

### 文档头部信息（以Verilog注释格式）
```
// Module: adder
// Description: functional block that computes the result of addition of the given inputs
// Ports: input[3:0] a, input[3:0] b, input c_in, output c_out, output[3:0] result
// Comments: a is computed with b along with the carry-in bit c_in to compute the result along with the carry-out bit c_out
```

### 完整的Verilog代码
```
module adder(
    input[3:0] a, 
    input[3:0] b, 
    input c_in, 
    output c_out, 
    output[3:0] result
);
assign {c_out, result} = a + b + c_in;
endmodule
```

## 4. 元数据提取和优化

为了提高检索效果，DeepV还进行了额外的元数据处理：

### 自然语言描述生成
- 每个模块都配有自然语言描述
- 这些描述与用户查询的自然语言格式对齐，提高了语义相关性

### 端口信息详细列出
- 明确列出所有输入输出端口及其位宽
- 帮助模型理解模块的接口规范

### 原始注释保留
- 保留原始代码中的所有注释
- 提供额外的设计意图和实现细节信息

## 5. 向量化处理

结构化文档随后被转换为向量表示：

### 嵌入模型选择
- 使用**all-MiniLM-L6-v2**嵌入模型
- 生成384维的高维向量
- 在检索准确性和内存占用之间取得平衡

### 批处理优化
- 由于数据集规模较大（20,392个模块），采用内存高效的批处理方式
- 确保整个向量化过程的可扩展性

## 6. 结构化的优势

这种结构化方法带来了多重优势：

### 语义相关性最大化
- 将描述性元数据放在文档开头，充分利用嵌入模型的注意力窗口
- 提高查询与文档之间的语义匹配度

### 上下文完整性
- 每个文档包含模块的完整上下文（结构+描述）
- 确保检索到的信息足够指导代码生成

### 计算效率
- 大多数模块少于100行代码，适合上下文学习
- 自包含的高质量示例，计算开销可控

通过这种系统性的结构化处理，DeepV成功地将原始Verilog代码转换为一个高质量、可检索的知识库，为后续的检索增强生成提供了坚实的基础。这种方法不仅确保了知识库的质量，还显著提高了检索的准确性和生成代码的功能正确性。
